# 0.2.0 — Supervised MVP

Tag: v0.2.0-supervised-mvp. This consolidates the completed development branches
into main, from the v0.1.0-milestone4b baseline.

## Delivered

- Durable action ledger, conservative authentication boundary and uncertain-action states.
- Deterministic section parsing and configurable engineering-update rules.
- WORK UPDATES 101 with aliases, code limits, quotation checks and image metadata checks.
- Supervised Gmail discovery, fresh re-evaluation, exact confirmation and one-shot reply sending.
- Legacy reservation preflight, truthful feedback, readable terminal output and offline config audit.
- Updated current setup/reference docs, with historical records clearly separated.
- Optional Jev and fake adapters retained; neither is used by supervised moderation.

## Acceptance evidence

The user ran the disposable-group test on their PC:
LIVE A was approved by one confirmed reply and manually observed published.
B and D returned REJECT with no send; C returned REVIEW with no send.
A later run skipped LIVE A as SENT and TEST 003 as LEGACY_OR_INCOMPLETE.
TEST 001 was subsequently confirmed separately and sent; its publication was
not reported. Gmail discovery does not establish current pending status.

Release validation: 295 offline tests, typecheck, config audit and diff check.
Automated tests use mocks and a loopback-only guard. No live Gmail or semantic
provider calls were made during release preparation. Remote CI results must be
checked on GitHub; local validation is not a claim that remote CI has passed.

## Included branches

milestone4a-gmail-readonly, milestone4b-controlled-reply,
milestone5a-safety-foundations, milestone5b-deterministic-product,
work-updates-101-deterministic and minimal-live-moderation.
The older fix/mime-fixture-ci branch is already incorporated.
The local work branch contains a patch-equivalent Milestone 3 commit; its
ancestry is consolidated without replacing the corrected current code.
Branch references are retained for history, not deleted.

## Compatibility deliberately retained

Old source-key reservations must remain blocking: removing them would permit
duplicate approval replies. Fake adapters, the single-message actuator diagnostic
and alternate profiles remain covered by tests. They are documented as diagnostic
or alternate paths, not the main workflow. No safety records are migrated or erased.

## Limits

Supervised disposable-group use only. Gmail authentication provenance remains
unproven; the explicit warned exception never makes a message TRUSTED.
Uncertain sends never retry automatically. Local ledgers do not coordinate
independent machines. No scheduler, autonomous moderation, rejection emails,
production deployment or live semantic assessment is introduced.

## Upgrade

~~~powershell
git fetch origin --tags
git switch main
git pull --ff-only origin main
npm ci
npm run config:check
~~~

Ignored local configs, tokens and ledger survive switching branches. Examples
do not overwrite them. Compare local YAML with the configuration reference;
keep .hmm/actions intact. Then follow [supervised setup](../supervised-moderation.md).
